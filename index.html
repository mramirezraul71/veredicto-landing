The problem

Coding agents are fast and confident. Too confident: they tell you "tests pass" with a broken test, "bug fixed" with the bug intact. If you sell agent-built work to clients, every unverified "done" is a liability sitting in your invoice.

Our gap research (September 2026) found that most tools delegate and trust the agent's own word. VEREDICTO closes that link with a different design: deterministic, fail-closed checks in a separate process — on your machine, with your own key. When it cannot verify, it says NOT_VERIFIED instead of guessing. It doesn't compete with your agent; it audits it.

How it works

  1. 1Delegate. You describe the task in plain language. The bridge hands it to your coding agent (Cursor, VS Code, Gemini — anything speaking ACP, the open agent protocol).
  2. 2Execute. The agent works in your repo and reports back its claim: "done, tests pass."
  3. 3Verify — separately. An independent verifier runs in its own process with a clean memory. It can't hear the agent's excuses. It re-runs the tests, inspects the diff, checks the expected files. Then it publishes the verdict: VERIFIED or NOT_VERIFIED — fail-closed, so when in doubt, it's a no.

The verifier is read-only: it never modifies your repo. You bring your own model key — we never see it, store it, or resell it.

What it's NOT

  • Not another coding agent. It doesn't compete with Cursor or Copilot — it sits on top and audits them.
  • Not magic. Deterministic checks: tests, diffs, expected files. What it can't verify, it doesn't promise.
  • Not a finished product. If you need a polished .exe today, this isn't for you — yet.
  • It never touches your keys. BYO-key is mandatory. If anyone asks for your API key to "manage" it, that's not us.

FAQ

Which agents does it work with?

Anything speaking ACP (Agent Client Protocol, open): Cursor, VS Code, Gemini and more. The driver auto-detects your agent from PATH. Switching agents is a ~10-line subclass.

How is this different from LangSmith / Langfuse / Braintrust?

Those observe and evaluate from inside the agent's own system. VEREDICTO verifies from a separate process that never talks to the agent — fail-closed. It's the difference between asking the student to grade their own exam and hiring an independent examiner.

Do you see my code or my API keys?

No. Verification runs on your machine; your model key stays with you (BYO-key). The mailbox only carries verdict events, never keys or source.
